**발생 단위 응답을 접어서(fold) 기준 일정을 복원하는 코드를 보면, 접은 `date`가 어디로 흘러가는지 끝까지 따라가라.**
캘린더 `GET /calendar-events?month=`는 `date`가 **발생일**이다(`api-specs/calendar.md` §1, 2026-09-13).
앱이 "창 안에서 가장 이른 발생일"을 `date`로 삼으면 그 값이 `PATCH`(전체 교체)의 `date`로 다시 올라가
**반복 앵커가 조회한 달로 이동**하고, 그 이전 발생·복용 기록이 서버에서 안 보이게 된다.

**Why:** PR #57 리뷰(2026-09-14)에서 발견. 접는 쪽 주석은 "그 뒤 발생은 반복 규칙으로 똑같이 그려낸다"고
했지만, *그 앞* 발생과 *편집 왕복*은 생각하지 않았다. MONTHLY 31일 앵커는 30일짜리 달에서 30일로 당겨진
발생을 앵커로 삼아 영구히 30일로 바뀐다.

**How to apply:** (1) 편집 화면·update 페이로드가 서버 응답에서 온 `date`를 그대로 되보내는지 본다.
(2) 앵커가 필요하면 단건 조회(`PATCH` 응답의 `date`는 시작일) 같은 다른 출처가 있는지 본다.
(3) `taken`처럼 발생일에 묶인 값과 앵커에 묶인 값을 같은 필드에서 뽑고 있으면 둘 중 하나는 틀린다.
